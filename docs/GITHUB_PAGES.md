# GitHub Pages deployment — ROMcraft Fieldnotes

This project is a **static-only Next.js App Router website**. A successful `next build` produces plain HTML/CSS/JS inside `out/`. GitHub Pages hosts it without Node, a database or an API server. No `next export` command is needed.

## 1. Local build

Install Node.js 22 and npm, then in the repository root:

```bash
npm install
npm run verify
```

`npm run verify` executes Markdown audits, automated Node tests, TypeScript checks, linting and the **static production build**. Check that `out/index.html`, `out/404.html`, `out/sitemap.xml`, `out/robots.txt`, `out/feed.xml`, and `out/og-card.png` exist. This repository deliberately does not bundle a compiled `out/` directory or `node_modules/`.

To preview the static output instead of the Next.js development server:

```bash
npm start
```

Visit `http://localhost:4173/`.

## 2. Push repository

Create a GitHub repository, preferably `romcraft-fieldnotes`. Commit the source and the **new `package-lock.json`** generated by `npm install`; never commit `node_modules`, `out`, the private `.env.local`, logs, or device backup images. `package-lock.json` makes `npm ci` reproducible.

```bash
git init
git add .
git commit -m "Launch ROMcraft Fieldnotes static site"
git branch -M main
git remote add origin https://github.com/OWNER/REPO.git
git push -u origin main
```

Replace OWNER and REPO. If your repo already exists, skip initialization and use your existing remote. The `.github/workflows/deploy-pages.yml` workflow runs on every push to `main` (or manually from Actions). The separate quality workflow runs for pull requests.

## 3. Enable GitHub Pages

In the repository open **Settings → Pages → Build and deployment → Source → GitHub Actions**. Then open **Actions → Publish ROMcraft to GitHub Pages** and run the workflow or push a new commit to `main`.

The workflow uses GitHub's official Pages actions to configure Pages, get its `base_path`, build with the right environment values, upload `out/`, then deploy. It automatically supports:

- **Project site:** `https://OWNER.github.io/REPO/` with `basePath=/REPO`.
- **User/org site:** `https://OWNER.github.io/` with `basePath=''` if the repository is named `OWNER.github.io`.

If you use a **custom domain**, configure it in GitHub Pages first. For canonical URLs, optionally set repository variable `ROMCRAFT_SITE_URL` to `https://your-domain.example` under **Settings → Secrets and variables → Actions → Variables**. A custom domain can change how Pages reports its base path; review the build output and verify links after deployment.

## 4. Local export targeting GitHub Pages

On Linux/macOS:

```bash
NEXT_PUBLIC_BASE_PATH=/REPO NEXT_PUBLIC_SITE_URL=https://OWNER.github.io/REPO npm run build
```

On Windows PowerShell:

```powershell
$env:NEXT_PUBLIC_BASE_PATH = '/REPO'
$env:NEXT_PUBLIC_SITE_URL = 'https://OWNER.github.io/REPO'
npm run build
```

Do **not** set a repo base path in local development unless you specifically want to test the prefixed URL. Next.js compiles `basePath` into the client bundle, so rebuild whenever it changes. Prefer the GitHub Actions workflow for actual publishing.

## 5. Post-deploy smoke tests

- Open home, `/guides/`, `/devices/`, nested `/devices/samsung-galaxy-a10-sm-a105f/device-dossier/` and `/search/` under the correct repo path.
- Test search terms `Magisk`, `VBMETA`, `EFS`; use a shareable `?q=magisk` link.
- Confirm static JS/CSS bundles load (no 404 for `/_next/` under the repo subpath).
- Verify light/dark switch, mobile menu, code copy, table of contents, and article navigation.
- Open `/robots.txt`, `/sitemap.xml`, `/feed.xml`, `/og-card.png` at the deployed base path.
- Check canonical URL and Open Graph URLs in page source: both must include `/REPO/` for project Pages.
- For accessibility, check keyboard-only navigation and Lighthouse accessibility performance in a real browser.

## Limits and cautions

- Static export cannot use server actions, request-time APIs, server-only sessions, dynamic headers, or Next.js runtime image optimization. Search here runs in the browser against a built-in index.
- GitHub Pages does **not** apply server security headers from `next.config.ts`; the repository removed those runtime-only settings. Do not use the website to receive secrets or account credentials.
- The repository includes a static `og-card.png` social preview and a `.nojekyll` marker. Do not remove these without adjusting metadata and hosting behavior.
- A successful static build is not the same as a third-party review of the research guides. Follow the editorial and safety policy before publicizing device-flashing instructions.
